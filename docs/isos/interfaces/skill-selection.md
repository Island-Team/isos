# R04 verified host-skill selection

[中文](../../../docs_cn/isos/interfaces/skill-selection_cn.md) · [Design](../design/skill-selection.md) · [First use](../usage/get-started.md#r04-native-skill-selection-target) · [Frozen cases](../../../tests/fixtures/skill_selection/README.md)

**R04 owner contract — IsOS selection slice independently reviewed; final merged-tip qualification pending.** IsOS owns the saved graph, exact P01 package pins, selected P04 generation and EOS child launch inputs. EOS owns ABI v2 descriptor admission, the confined worker, capability Broker, Dispatcher and SkillService. A package installation alone does not activate a skill. This selection supplies libraries, never a graph-authored skill sequence, WorkflowService or an actuator route. The [EOS host ABI contract](https://github.com/Island-Team/Island-eos/blob/refactor%28v2%29/runtime-main/docs/eos/interfaces/skills/native/host-abi.md) owns guest execution.

## Saved graph input

Only the selected `isos.process.component@v0.1` node at `isos/process/component/eos`, with `settings.role:"eos"` and resolved executable `aether-runtime`, may have optional `settings.skill_libraries`. The `bridge`, `config` and any other EOS-role component fail at their `/settings/skill_libraries` pointer even though their role is also `eos`. G06's `@v0.1` component setting catalog advertises the field; this owner check enforces the narrower runtime-node predicate. Absence or `[]` means no external host catalog and no `EOS_SKILL_SELECTION_FILE`. Every nonempty entry is exactly `{ "package": { "id": "namespace/name", "version": "x.y.z" }, "library": "lib/island/skills/example.skill.so" }`; unknown keys fail. `package` is the exact P01 release pin, and `library` is a package-relative POSIX path to one native ABI v2 shared library, not a glob, directory, command or URL. The graph cannot name a host executable, worker argument, skill handler, callback, step or privileged capability. The EOS process node retains its usual role, arguments and dependency rules.

| Field | Type / unit | Purpose and validation |
| --- | --- | --- |
| `settings.skill_libraries` | array / entries | Optional, at most 16 entries; only on the EOS `@v0.1` component. Each entry has exactly `package` and `library`. Sort by `(package.id,package.version,library)` in the generated selection, reject repeated tuples, and preserve saved graph bytes and array order until explicit Apply. |
| `package.id` | string / package ID | Required canonical lowercase `namespace/name`; P01 verifies exactly this installed or linked schema-2 release. For a selected skill, at most 96 ASCII bytes, matching EOS's lifecycle-event limit. |
| `package.version` | string / release version | Required exact version accepted by P01; no latest/range resolution. The target pre-stop gate for a selected skill requires at most 64 ASCII bytes, a leading digit, at least three nonempty dot-separated segments, and only ASCII letters, digits, `.`, `-`, `+`. The current P01/EOS selection grammar still permits empty segments such as `0..1`; R04 event admission accepts such a pin only when it exactly matches the selected pair. Build metadata, including uppercase letters, is preserved exactly. |
| `library` | string / relative POSIX path | Required UTF-8, 1–256 bytes, components neither empty, `.` nor `..`, no backslash or NUL, suffix `.skill.so`. The resolved target must be a non-symlink regular file of 1–64 MiB; no symlink component, directory scan or recursive discovery. |

The P01 graph pin collector includes every selected `package` at its exact `/cores/isos/layers/process/groups/component/nodes/<id>/settings/skill_libraries/<index>/package` pointer. For each entry IsOS obtains a fresh P01 `VerifiedPackage`, requires release `kind:"skill"`, checks the canonical payload root, selected file identity and SHA-256, and rejects duplicate library paths or changed linked payload. A verified package can contain other files, but only the explicit list is selected. The same package may contribute more than one explicitly listed library; EOS later rejects duplicate skill identities across all libraries. Legacy `1.0.0` graphs and old `eos.control.skill@v1.0` nodes do not acquire this field or execution behavior.

**Remaining candidate-preflight gate:** the current implementation candidate has not yet enforced the selected-skill-only 96/64-byte and version grammar above. Validate/Apply must reject at the indexed `package/id` or `package/version` pointer before publication; Run/Restart must recheck before stopping an active deployment. This keeps a selected package from passing IsOS but failing EOS's event emitter after launch. The [R04 event design](../design/events.md#r04-selected-skill-event-admission-design) and [fixture](../../../tests/fixtures/r04_skill_events/README.md) depend on this gate; the generic P01 package grammar remains unchanged.

For a selected skill release, IsOS additionally checks the opened selected library, P01 `receipt.json` and `release.json`, and every regular file in the verified payload tree. Each must be owned by IsOS's effective UID and have no group or other write bits (`mode & 0o022 == 0`). The selected library must also meet its 1–64 MiB bound; metadata and payload files retain P01/EOS size bounds. An unsafe file fails before Apply publication or Run/Restart stops the active process. EOS repeats the same ownership and mode checks before staging. An unrelated payload file with write bits is still part of the verified skill package and therefore fails.

The G06 catalog describes this field truthfully on `isos.process.component@v0.1` with additive `data_type:"object_array"`, `min_items:0`, `max_items:16` and an `items_schema` JSON Schema object. The item schema has `type:"object"`, `additionalProperties:false`, required `package` and `library`; `package` is another no-extra object requiring string `id` and `version`; `library` is a nonempty string of at most 256 characters. The EOS registry accepts only its bounded local schema subset (`type`, `properties`, `required`, `additionalProperties`, `minLength`, `maxLength`, `pattern`), at most 8 KiB and depth 3, with no `$ref` or unknown keyword. IsOS then applies the stricter byte/path, exact owner-node and P01 checks above. Existing setting metadata serialization remains unchanged when these new fields are absent. The `@v1.1` catalog and legacy graph remain unchanged; downstream U01 forms receive an object-array descriptor rather than a misleading string setting. The IsOS `ProcessSettings` parser and G06 aggregate-catalog adapter must both be extended; merely documenting the field does not admit it.

IsOS owns and publishes the `@v0.1` component descriptor with both its existing `env_from` setting and `skill_libraries`, using EOS's additive generic `SettingType::ObjectArray` support. The historical EOS `@v1.1` catalog descriptor remains a compatibility input, not the owner of the new IsOS type. IsOS's older-EOS fallback clone may supply `env_from` for skill-free graphs but must not synthesize `skill_libraries` or admit a nonempty selection. P05's exact `host-skill-abi-v2` claim gates the selected runtime binary.

## Selected generation and EOS handoff

For a nonempty list, Apply adds one IsOS-authored `isos/skill-selection.json` to the immutable P04 `v2/<active_revision>/<generation>/` leaf. Its exact SHA-256 appears once in schema-2 `manifest.json.files`; its selected packages appear in `manifest.json.packages`. The file is private `0600` beneath `0700` parents. Its compact sorted JSON fields are exactly:

The complete serialized file is at most 65,536 bytes (64 KiB), matching EOS's bounded selection reader. IsOS rejects a larger rendered file at the EOS `settings.skill_libraries` pointer before Apply publication or Run/Restart replacement, including when long verified linked-package paths cause the excess.

```json
{
  "schema_version": 1,
  "active_revision": "<64 lowercase hex SHA-256 of saved graph bytes>",
  "libraries": [{
    "package_id": "example/native-skill",
    "package_version": "0.1.0",
    "package_root": "/absolute/isos/data/packages/example/native-skill/0.1.0",
    "payload_root": "/absolute/verified/payload/root",
    "receipt_sha256": "<64 lowercase hex SHA-256 of P01 receipt bytes>",
    "release_sha256": "<64 lowercase hex SHA-256 of verifier-owned release snapshot>",
    "payload_sha256": "<64 lowercase hex P01 tree digest>",
    "library": "lib/island/skills/example.skill.so",
    "library_sha256": "<64 lowercase hex SHA-256 of library bytes>"
  }]
}
```

`package_root` is the absolute private P01 metadata store; `payload_root` is the P01 verified payload root, which may be a linked source. Neither graph authors nor browser callers supply either path. The receipt, release, payload and selected library digests bind each exact pin and file; P04's manifest binds the selection file to the saved graph, installed inputs and selected EOS binary. `active_revision` equals the saved-byte revision and the manifest `revision`, not the EOS projection digest. The selection file omits `generation`, because P04 computes generation from final file hashes; the leaf path and manifest supply it without a circular hash. IsOS writes no selection file for an empty list and rejects a stale unexpected selection file in a selected generation.

The selected EOS `aether-runtime --capabilities` must advertise exact `host-skill-abi-v2` when the list is nonempty. An older binary fails P05 `reader_feature_unsupported` at the EOS component `/node_type` before Apply publication, Run/Restart replacement or guest code. After the existing R03 managed-grant preflight, IsOS injects only `EOS_SKILL_SELECTION_FILE=<absolute selected isos/skill-selection.json>` into the selected EOS child. It removes inherited or authored values of this reserved variable from every other child, and rejects an authored conflicting EOS value or owner-reserved skill-selection argument before stopping the active run. The selection file is data, not a bearer grant; R03 role grants remain independent.

Run and Restart verify the saved bytes, V2 selection and required marker, complete manifest/file inventory, all pinned P01 receipts, fresh library digests and selected EOS feature before stopping any active child. A missing, changed, unlisted, unsafe or wrong-revision selection fails pre-stop and leaves current PIDs, run ID, active revision and grants intact. The IsOS candidate now inspects a selected ABI before stopping the old child; independent review and real EOS replay remain pending. No G03 or legacy-flat fallback admits a skill selection. Re-Apply of the same saved revision after a package or binary change selects a new immutable generation; only explicit Restart activates it. A manager or child restart rechecks the selected generation; an automatic same-run EOS child restart uses the same selected file and R03 run identity. Stop retires the R03 grant bundle after child reap; no skill worker may outlive its EOS parent.

EOS independently verifies the selected manifest/file/revision, digest and path identities before any confined query. For linked packages EOS opens the exact nofollow file, checks and hashes the opened bytes, copies those bytes to its own private read-only staging file, and loads only that copy inside the worker. It never `dlopen`s a caller pathname in the supervisor. Its worker validates ABI sizes, descriptors and declarations before a handler invocation. IsOS's pre-stop P01 check and EOS's before-worker check are both required; neither substitutes for the other.

## Candidate ABI preflight (IsOS implementation candidate)

Owner: the IsOS deployment manager calls the selected EOS `aether-runtime` private process interface; EOS owns the result and ABI inspection. Transport is one direct child process with a cleared, manager-owned environment and one JSON line on stdout. This runs only for a nonempty managed skill selection, after P01/P04/P05 and process-spec checks, before `managers.remove(name)`, old-child stop, candidate run-scope publication or `deployment_starting`. An empty selection follows the existing path and gains no executable host catalog. No unverified capability, package or graph bypass is available.

IsOS creates a new candidate run ID and R03 grant bundle without publishing its run scope. It invokes the **same selected and verified** `aether-runtime` executable with `--skill-catalog-preflight --profile <selected-v2-leaf>/eos/graph.json --run-id <candidate-run-id>` and the actual selected `--node-types` arguments. It passes `EOS_CONTROL_GRANTS_FILE=<candidate-verifier>`, `EOS_SKILL_SELECTION_FILE=<selected-v2-leaf>/isos/skill-selection.json`, and only the effective validated `ISOS_GPU`/`ISOS_ROS` asset selectors that the selected EOS child would receive; it passes no bearer grant. Authored `settings.env`, removed secret-source names and resolved `env_from` values use the normal child launch precedence. IsOS rechecks those selectors before old-child stop and at actual launch. The private command rejects launch options for a listener, socket, journal, adapter, backend or scene. EOS may run only a library constructor and ABI query in a confined inspection worker. The probe cannot start a listener, simulator, adapter, Dispatcher or guest `execute` handler, and cannot publish readiness. EOS checks the exact saved revision, schema-2 leaf/manifest, candidate verifier/run binding, P01 package and library bytes, ABI v2 descriptors, declared Broker coverage, a static deployment binding for every declared primitive, duplicate identities and the complete encoded `ListSkillsResponse` 3 MiB limit. It reaps every inspection worker and removes its private staging before success. The [EOS private preflight contract](https://github.com/Island-Team/Island-eos/blob/cf48e439c88d7938f5d5e9cf839b066883359d36/docs/eos/interfaces/skills/native/host-abi.md#private-candidate-catalog-preflight-target-design--not-implemented) defines the closed result and its pure, shared readiness validator. Live health, terminal stop fence, adapter and Dispatcher checks remain launch or invocation gates; this probe makes no R05/R06 physical stop claim.

The stdout limit is 16 KiB and stderr is captured to 16 KiB for disposal only. IsOS accepts exactly one UTF-8 JSON line, with no duplicate or unknown keys. Success requires exit `0` and exactly `schema_version:1`, `ok:true`, `active_revision`, `generation`, `run_id`, `selection_sha256`, and `libraries`. The revision, generation and digest are lowercase SHA-256 strings. `run_id` equals the candidate identity. `libraries` has 1–16 entries in the selected-file order; each entry has exactly `package_id`, `package_version`, `library`, `library_sha256`, `abi_version:2`, and `skill_count` in 1–256. IsOS compares every echo with the saved revision, selected leaf, candidate run, exact selected-file digest and ordered verified package pins/library digests. A failure requires nonzero exit and exactly `{ "schema_version":1, "ok":false, "stage":"abi", "code":"abi_descriptor_invalid" }` in the same one-line shape. `stage` and `code` must be one of the closed EOS pairs below; no message, path, schema, grant, stderr or guest text is accepted as protocol data.

| EOS stage | Allowed EOS codes |
| --- | --- |
| `input` | `preflight_arguments_invalid`, `preflight_grants_invalid`, `preflight_profile_invalid` |
| `selection` | `selection_invalid`, `selection_revision_mismatch`, `selection_manifest_invalid`, `selection_digest_mismatch`, `selection_handoff_incomplete` |
| `package` | `package_invalid`, `package_changed`, `package_unsafe`, `library_changed` |
| `elf` | `library_not_elf`, `library_dependency_unsafe` |
| `worker` | `worker_spawn_failed`, `worker_sandbox_failed`, `worker_inspection_failed`, `worker_timeout`, `worker_reap_failed` |
| `abi` | `abi_library_invalid`, `abi_descriptor_invalid`, `abi_schema_invalid`, `abi_capability_unowned` |
| `catalog` | `catalog_duplicate_identity`, `catalog_capacity`, `catalog_broker_unavailable`, `catalog_binding_unavailable`, `catalog_list_oversize` |

IsOS enforces a hard **90-second wall-clock deadline** for the entire probe, including package reads, staging and inspection. At the deadline it terminates the probe process group and makes a separately bounded reap attempt; a late success can never override the timeout. A signal also maps to timeout. A P01-valid selected release version such as `1` can pass IsOS `valid_pin` but fail EOS `valid_selected_pin`, which requires at least three dot segments. EOS returns `selection/selection_invalid`; IsOS maps it to `skill_catalog_preflight_rejected` before old-child stop and retires candidate grants with a checked result. IsOS event collection retains the exact P01-validated selected pin in safe fields; it must not drop it by applying EOS's stricter parser to the event. A valid nonzero `ok:false` maps to `skill_catalog_preflight_rejected`; missing, multiple, oversized, malformed or mismatched output, or exit/`ok` disagreement maps to `skill_catalog_preflight_invalid_output`; deadline or signal maps to `skill_catalog_preflight_timeout`; unconfirmed probe-process or candidate-grant cleanup maps to `skill_catalog_preflight_cleanup_unconfirmed` and takes precedence. These are fixed IsOS schema-1 diagnostics at `stage:"preflight"` and empty `path`, under `deployment_preflight_failed`. The manager logs only safe revision, generation, candidate run/correlation ID, EOS stage/code when valid and IsOS code. It never logs probe output, stderr, private paths, raw schema, bearer grants or library bytes. The first failure belongs to the **manager-session** cursor because the candidate run scope is unpublished; `isos logs all --current` may still show the old run.

On any probe failure or later pre-stop check failure, IsOS explicitly retires the candidate bundle through a checked `Result` path and confirms probe process-group cleanup. Current `Supervisor::stop()` and Drop merely print retirement errors and cannot prove cleanup. A failed retirement produces `skill_catalog_preflight_cleanup_unconfirmed`, leaves old PIDs, run ID, active revision, grants and run scope untouched, and requires operator repair before another replacement. A rejected candidate needs no recovery run. After `ok:true`, IsOS rechecks saved graph revision, complete selected-generation inventory, exact executable bytes, candidate grants and P01 receipt/release/payload/library bytes immediately before old-child stop and candidate spawn. The successful probe result is never launch authority. The new EOS process repeats managed admission, ABI inspection and shared static readiness validation against fresh staged bytes before ready; automatic same-run EOS restarts repeat launch admission too. A change after old-child stop uses the existing recovery path and is reported as a candidate startup failure.

## Diagnostics and evidence

P01 package tamper retains its existing `package_changed`, `package_unsafe_path` or `package_missing_file` diagnostic at the selected entry `/package`, before R04 semantics. P04 snapshot or generation damage retains `generated_manifest_mismatch` at `stage:"snapshot"`; P05 missing host feature retains `reader_feature_unsupported`. R04-specific semantic failures use the schema-1 API diagnostic shape `{code,path,message,stage}` with a sanitized repair action and the exact escaped JSON Pointer: `skill_selection_invalid` (`graph`) for wrong owner, count, shape or duplicate; `skill_package_incompatible` (`package`) for a verified non-skill release; `skill_library_unsafe` (`package`) for invalid path/type/symlink/size; and `skill_library_changed` (`package`) for a selected file digest mismatch. Direct CLI calls exit nonzero. Events include safe code, pin, revision, run/correlation ID when present, but never raw package paths, library bytes, bearer grants, worker stderr or loaded code. A pre-start error uses the manager-session first-failure cursor; after admitted start the run cursor finds EOS ready or rejection.
