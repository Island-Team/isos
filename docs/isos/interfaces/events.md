# Shared deployment events

[中文](../../../docs_cn/isos/interfaces/events_cn.md) · [Configuration and log storage](configuration.md) · [Local log API](local-api.md) · [First use](../usage/get-started.md) · [P06 task](../../../../Island-eos/docs/island/implementation-todo.md)

**P06 implementation contract.** IsOS owns the manager session, deployment run identity, private per-source logs, unified `events.log`, and ingestion of selected child events. EOS and EGIA own their emitted event meanings. IsosUI reads the IsOS stream; it does not infer health from an event. P06 adds the common sanitized JSON Lines (JSONL) envelope. P07 adds cursor retention and first-event navigation across rotation.

## Producer and collector boundary

One UTF-8 JSON object followed by `\n` is one record. A raw child line is at most 8,064 bytes including newline; this reserves 128 bytes for IsOS normalization and its observed PID. A stored line, including newline, is at most 8,192 bytes. Producers shorten an already sanitized `message` at a UTF-8 boundary until the complete record fits; a field's own limit does not exempt the line from this limit. IsOS admits only bounded, valid records from the authenticated manager or a selected direct-child pipe. It writes admitted records to `data/logs/<deployment>/<source>.log` and the unified `events.log` with owner-only `0700` directory and `0600` file permissions. A source-file cap may direct a new source only to the unified stream. Plain stdout/stderr, malformed JSON, unknown top-level fields, duplicate JSON keys, oversized lines and unregistered child event codes are not copied into either IsOS stream; the collector drains an oversized line through its newline and resumes at the next record. The owning core retains its own full diagnostics.

| Field | JSON type / unit | Purpose, absence, validation and compatibility |
| --- | --- | --- |
| `timestamp` | RFC 3339 UTC string / milliseconds | Required event time. IsOS generates it for manager events and preserves a valid selected-child time. Reject non-UTC or malformed child values. |
| `level` | `trace`, `debug`, `info`, `warn`, `error` / — | Required severity; preserves the existing filter order. A failure is `error`, a safe refusal may be `warn`. |
| `source` | ASCII string / source ID | Required, 1–48 letters, digits, `_` or `-`. The supervisor binds selected EOS runtime source `eos`, EOS HTTP bridge `bridge`, EOS config server `config`, and EGIA `egia` to their respective direct-child roles. Raw MuJoCo child diagnostics stay in the separate EOS owner log; `mujoco` is reserved for a future verified shared producer. An arbitrary child cannot claim `isos`, `packages` or another child's source. |
| `core` | `isos`, `eos`, `egia` / owner ID | Required runtime owner. IsOS workbench, package, graph and independent-service events use `isos`; EOS backend lifecycle events use `eos`. The collector derives the expected owner from the selected process and rejects disagreement. |
| `node_path` | JSON Pointer string or null / saved-graph path | Optional; normalize absence to null. A nonnull value is a canonical, escaped saved-graph pointer ending exactly at `/cores/<core>/layers/<layer>/groups/<group>/nodes/<node>`, at most 512 UTF-8 bytes, and names the node responsible for the event. Member pointers such as a trailing `/package` are rejected. The admitted graph segment grammar excludes `/` and `~` in IDs; pointer escaping does not authorize otherwise invalid IDs. EOS expands any internal four-part node path before emission. No local filesystem path is admitted. |
| `event_code` | lowercase ASCII string / stable code | Required, 1–64 letters, digits or `_`. The producer owns its code list; IsOS admits only codes in its versioned role policy copied from reviewed owner contracts, never arbitrary child text. Existing readers that omit the field remain readable; P06 writes it. |
| `run_id` | ASCII string / opaque run or manager-session ID | Required, 1–64 letters, digits, `_` or `-`. `m...` identifies the manager session before launch; `r...` identifies one deployment run. The collector supplies or checks the supervisor-assigned value and never trusts a child to select another run. Existing lines without it remain readable. |
| `correlation_id` | ASCII string or null / opaque request ID | Optional; normalize absence to null. Same syntax and length as `run_id`. It links a request, child launch, operation or failure without embedding user text or credentials. |
| `message` | string / UTF-8 bytes | Required concise explanation, individually at most 8,192 bytes and further shortened for the line bound. Internal messages use reviewed templates; child messages must pass the role's safe-message policy. Never store raw error chains, prompts, frames, credentials or environment values. |
| `fields` | object / bounded metadata | Optional; normalize absence to `{}`. At most 12 allowed scalar keys and 4 KiB serialized; key length 1–48 ASCII letters, digits, `_` or `-`, string values at most 256 UTF-8 bytes and without controls. No nested values, arbitrary text, paths, raw payloads or secret values. Each event code has an allowed typed key set. |
| `pid` | positive integer or null / OS process ID | Optional; normalize absence to null. The raw child envelope omits `pid`; IsOS adds the observed direct-child PID after validation. Manager events use the manager PID. A child cannot spoof it. It is process metadata, not readiness proof. |

### Role policy and legacy socket

The IsOS release carries a reviewed, versioned role policy in its target `src/runtime/event_policy.rs`. That table is the collector's code, typed-field, severity, node-ownership and suppression-class allowlist; it is pinned against the selected EOS and EGIA owner contracts and tested with their release fixtures. No child may extend it by claiming a new code in JSON, a capability response, or a graph value. The initial EOS policy copies the exact code families from the reviewed EOS P06 owner event contract: runtime `eos_starting`, `eos_ready`, `eos_start_failed`, `eos_stopping`, `eos_stopped`, `eos_package_admitted`, `eos_package_provenance_unavailable`, `eos_backend_ready`, `eos_backend_lost`, `eos_stop_unconfirmed`, and runtime-only `eos_events_suppressed`; bridge `bridge_starting`, `bridge_ready`, `bridge_start_failed`, `bridge_stopping`, `bridge_stopped`; config `config_starting`, `config_ready`, `config_start_failed`, `config_stopping`, `config_stopped`. EOS `node_path` must name an admitted EOS node. The EGIA role uses the reviewed 16-code P06 owner policy pinned in `tests/fixtures/jsonl_events/egia-role-policy.json` and remains closed to unlisted codes; a selected EGIA child and a valid `run_id` alone do not grant arbitrary event admission. IsOS alone constructs `events_suppressed` with `source:isos`, `core:isos` and bounded `suppressed_source`, `suppressed_event_code`, and `count` fields. A child claiming that code is rejected. These role policies also reject child code/field combinations that are valid only for a different selected process.

### R04 native skill child events — implementation review

The R04 IsOS policy change depends on EOS SkillService commit `192fbfa6fbed1e9b6a20dd8dc95501625b02d081` and the [EOS owner event contract](../../../../Island-eos/docs/eos/interfaces/events.md). The IsOS implementation admits only the two codes below to the selected `eos` runtime role, after the existing selected-child pipe, active-run and observed-PID checks. A graph declaration, package descriptor, skill guest, capability response, legacy socket append, bridge, config or EGIA child cannot authorize either code. All other P06 role entries and field validators keep their existing meanings.

| Code | Exact admitted stored/raw envelope and typed fields | Policy |
| --- | --- | --- |
| `eos_skill_execution` | `source:"eos"`, `core:"eos"`, `node_path:null`, exact message `EOS native skill execution lifecycle`; `level:"info"` for `stage` `queued`, `running`, `completed`, `level:"error"` for `failed`. `fields` contains exactly `execution_id`, `package_id`, `package_version`, `stage`, `reason_code`, `worker_reaped`, `worker_exit_code`. | `execution_id` starts `ex-`, is at most 80 lowercase ASCII letters, digits, `.`, `_`, `-`; `package_id` is the selected P01 lowercase `namespace/name` slug, at most 96 ASCII bytes; `package_version` is the exact selected version, at most 64 ASCII bytes, starts with a digit, has at least three dot-separated segments (empty segments remain admissible in the current selected P01/EOS grammar) and permits letters, digits, `.`, `-`, `+` (including uppercase build metadata). The separate candidate pre-stop gate will reject unsupported selected pins before replacing an active run. `reason_code` is a fixed EOS-host-owned `worker.*` token, 1–128 lowercase ASCII letters, digits, `.`, `_`, `-`; for this pinned producer, `queued` requires `worker.queued`, `running` requires `worker.running`, `completed` requires `worker.succeeded`, and `failed` allows only the reviewed host outcomes in the [R04 fixture](../../../tests/fixtures/r04_skill_events/cases.json). No guest text, internal error string or arbitrary `worker.*` suffix is admitted. `worker_reaped` is Boolean or null, `worker_exit_code` is a signed 32-bit integer or null. The two fields are null for queued/running; completed requires an observed reap; a terminal record reports only observed process facts, and a pre-spawn failure may have both null. `correlation_id` is exactly `skill_` followed by 32 lowercase hexadecimal characters from the EOS request hash; `run_id` is the active IsOS deployment run. Raw child JSON omits `pid`; IsOS stores its observed direct-child PID. |
| `eos_skill_stop_unconfirmed` | `source:"eos"`, `core:"eos"`, `node_path:null`, `level:"error"`, exact message `EOS native skill stop unconfirmed`, `fields` exactly `{"state":"failed","reason_code":"skill_stop_unconfirmed"}`. | The correlation is a valid shutdown ID when supplied, otherwise null. It covers an unreaped worker or pending Dispatcher cancellation and cannot be interpreted as confirmed physical stop. No package or execution fields are accepted on this code. |

For both codes, P06's timestamp, raw/stored byte limits, duplicate-key rejection, safe scalar bounds, active-run binding and selected-process ownership still apply. For `eos_skill_execution`, IsOS also compares the exact `package_id`/`package_version` pair with the selected skill pins in its admitted P04 generation; an empty selection cannot emit this code. A valid envelope with a missing/extra field, wrong type, wrong stage/level or reason pairing, nonnull node, spoofed PID, wrong role/run, unselected or unsafe pin, or child-authored `events_suppressed` is rejected and counted as `log_ingest_rejected`; it is never copied into either shared log. A selected skill pin mismatch increments the bounded status map `log_ingest_rejected_by_reason.skill_pin_mismatch`; a node ownership mismatch remains `node_owner`. The accepted first `error` remains eligible for P07's pinned run anchor, even if the display query filters out `source=eos` or uses `level=error`. Subsequent events are ordinary position-ordered lines. Retained rotation must continue an old cursor across a backup without a gap; expired segments report `log_cursor_expired` with a new cursor while preserving the sealed anchor. A collector/write loss reports `log_collector_gap` with known count or null, never a clean continuity claim. [R04 fixtures](../../../tests/fixtures/r04_skill_events/README.md) freeze the negative and cursor examples; the EOS SkillService cross-owner runtime replay remains an implementation gate.

The schema-1 manager-socket `log_append` request authenticates only the same-UID local peer, not a selected EOS, EGIA, bridge or config process. Its caller-provided `role`, `source`, `event_code` and `message` cannot establish owner identity or readiness. P06 keeps the historical request shape and `{"accepted":true}` for syntactically valid nonreserved requests, including a historical `source:"eos"` request, but normalizes every such append to `source:legacy_external`, `core:isos`, fixed `event_code:legacy_external_event`, fixed safe `message:"Legacy external event received"`, caller severity, manager-session `run_id`, generated request correlation and manager PID. It drops the untrusted requested source, code and message from the shared streams. The existing reserved-source rejection remains. `legacy_external_event` never affects selected-child readiness or deployment health. The verified selected-child stderr pipe is the only P06 route to authoritative `eos`, `bridge`, `config` or `egia` source records.

An IsOS package failure before launch uses the manager session and one request correlation. Its `package_load_failed` detail and `deployment_preflight_failed` summary share that correlation. `null` means a receipt value was unavailable; it is never guessed:

```json
{"timestamp":"2026-11-01T10:00:00.000Z","level":"error","source":"packages","core":"isos","node_path":"/cores/eos/layers/process/groups/mujoco/nodes/sim","event_code":"package_load_failed","run_id":"m42-abc","correlation_id":"p3","message":"Deployment package load failed before launch","fields":{"package_id":"island/mujoco-sim","package_version":"0.1.1","source_kind":null,"release_sha256":null,"payload_sha256":null,"stage":"payload"},"pid":42}
```

After launch, a selected EOS child emits `eos_ready` on stderr. Its raw JSONL object omits `pid`; the collector keeps validated owner, node, run and correlation fields and assigns the observed child PID. The stored event is:

```json
{"timestamp":"2026-11-01T10:00:01.000Z","level":"info","source":"eos","core":"eos","node_path":null,"event_code":"eos_ready","run_id":"r7-cde","correlation_id":null,"message":"EOS runtime ready","fields":{"state":"ready","node_count":1},"pid":4242}
```

## Run identity and lifecycle

The manager creates one session ID when it starts. Package install/link, draft Validate, Apply, version checks and any rejected Run/Restart preflight use that ID and, when a request can be identified, a fresh `correlation_id`. They remain manager events even when an older deployment is active. The first accepted `deployment_start` allocates a new deployment `run_id` after all graph, package, reader, generation and secret preflight passes, immediately before the first child spawn. All children in that generation receive it; a repeated Start against an already active generation returns the existing ID and emits no duplicate startup/ready summary. Restart preflight failure leaves the active run unchanged and logs under the manager session. A Restart that begins replacing children uses a new run ID; if replacement fails, that attempt has a terminal failure, and any restored previous specification runs under a distinct recovery ID. Automatic child restarts inside one admitted deployment run retain that run ID and use a new correlation for each attempt. Stop and terminal outcomes use the active run ID. IsOS status, rather than the last log line or PID, remains authoritative for current readiness.

On an automatic child restart, IsOS emits `child_restart_attempt` (`warn`) and, after owner readiness, `child_restart_ready` (`info`) with the same fresh `correlation_id` and unchanged deployment `run_id`. Their only field is `process_id`: a 1–48 byte validated ASCII child ID, used to identify the restarted selected process. These manager events carry no raw command or environment values.

Before a deployment API operation returns a prelaunch failure, IsOS emits `deployment_preflight_failed` (`error`, `source:isos`) under the manager-session ID with a new correlation. Its fixed message is `Deployment preflight failed before launch`; known structured diagnostics contribute bounded `diagnostic_code` and `diagnostic_path` fields. A path longer than 256 bytes or containing a control character is omitted while the fixed failure event remains. A failure after `deployment_starting` belongs to that run instead. A failed first Start is stopped and removed from the active map; a later retry gets a new run ID and cannot turn the failed run ready.

IsOS logs one `deployment_starting` summary before its first child, one `deployment_ready` after all required readiness checks, then state transitions and one terminal `deployment_stopped` or `deployment_failed` event per run. EOS and EGIA each emit one startup/ready summary when their own prerequisites are complete, then transitions and terminal outcomes. A bound listener, started PID or successful probe is not an owner-ready event. A failure before launch is emitted with the manager-session ID before the API/CLI returns its sanitized error. A child failure after run allocation carries the deployment run ID. An event that cannot be persisted is observable through a bounded drop/error counter; logging failure does not block actuator stop or process reap.

## Selected EOS and EGIA handoff

IsOS passes the selected EOS runtime `--run-id <id>`. For a verified managed MuJoCo child, it also passes **both** `--backend-release-sha256 <64 lowercase hex>` and `--backend-payload-sha256 <64 lowercase hex>`, or neither flag for a runtime without that child. The exact `{id,version}` comes from the admitted `node.package`, and IsOS rechecks it against the P01 receipt before passing these digests. EOS validates the flags before opening a socket or device, supervises the simulator itself, and emits sanitized JSONL lifecycle events on stderr. IsOS owns the resulting top-level `eos.log` and `events.log`; EOS's `--log-dir` points to separate private `data/logs/<deployment>/owner/eos/` for raw simulator and owner diagnostics. The digests are provenance, not actuation authority. IsOS neither installs the package on EOS's behalf nor reads the simulator socket.

The selected managed EGIA child receives `ISOS_RUN_ID=<deployment-run-id>` as a nonsecret environment binding. EGIA validates it before startup; malformed values fail closed, and standalone EGIA without the binding mints its own local run ID. EGIA's own structured events are collected from its selected pipe only after the IsOS supervisor verifies the active run and allowed `egia` source; a mismatched child ID is rejected. An EGIA listener or PID does not mean its EOS discovery and safety gate are ready. IsOS never converts a graph edge into an EGIA command.

## Sanitization, suppression and errors

The emitter constructs a fixed event code and safe message template. IsOS then enforces a per-role code and field allowlist, typed values, the exact package pin and digest shapes, and the whole-line bound before storage. Package events use `package_id` and `package_version` from the requested or verified exact pin; when available, `source_kind`, `source_commit`, `asset_sha256`, `release_sha256` and `payload_sha256` come from the rechecked receipt. Missing provenance stays null. Never copy a raw graph, command arguments, full exception, model prompt, frame, secret name/value, arbitrary environment variable or absolute source path into `message` or `fields`. Reject or redact unsafe input before it reaches either stream; do not rely on the UI filter as sanitization.

The first ready, warning, failure and terminal event of a state change is never suppressed. Repeated identical noncritical periodic health or frame diagnostics are counted by `(run_id,source,node_path,event_code)` and replaced by one bounded `events_suppressed` summary at most once per 60 seconds and at terminal flush. A high-rate producer cannot evict the first failure by repeatedly logging the same condition. The collector has bounded memory and a reserved path for lifecycle/failure events; if overloaded, it drops lower-severity repetition first, increments a visible counter and never silently claims the dropped event was stored. One log write or collector outage cannot delay stop. P07 adds current-run cursor navigation and retention across file rotation; P06 keeps the existing private rotation limits and emits the first event promptly.

`GET /api/isos/v1/logs?source=all&limit=100` and `isos logs all --level info` read accepted events through the existing API and CLI. A rejected child line is not an API error; it increments `log_ingest_rejected` with a bounded reason code and no raw line. A failed IsOS append or log-store initialization reports `log_write_failed` in manager status/diagnostics without recursion. Restart reaps old children before writing their `deployment_stopped` event, so a stalled collector does not hold those children live. Existing schema-1 `log_append` remains same-UID owner-only and accepts its historical small request, but follows the untrusted legacy normalization above; its reply still contains `{"accepted":true}` on success. The P06 fixture set under [tests/fixtures/jsonl_events](../../../tests/fixtures/jsonl_events/README.md) freezes positive, negative, high-rate and stop cases; implementation must replay actual EOS and EGIA child streams before closure.
