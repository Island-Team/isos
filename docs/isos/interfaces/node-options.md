# Node setting options

[中文](../../../docs_cn/isos/interfaces/node-options_cn.md) · [Local API](local-api.md) · [MuJoCo catalog](mujoco-catalog.md) · [Verified packages](package-verification.md)

**P03 IsOS owner contract.** IsOS resolves display options for a graph draft or the exact saved graph. The caller is IsosUI or another owner-authorized loopback client. The transport is `GET` or `POST /api/isos/v1/node-options` with the existing schema-1 `{schema_version,ok,data,error}` envelope and loopback Host/Origin checks. An option is presentation data, never a package receipt, graph admission, launch capability, or authority to run an actuator. IsOS rechecks the exact current graph and package pin during Validate, revision-checked Apply, Run, and Restart. EOS owns the generic hardware node types and compiled adapter capability; the MuJoCo package contributes only its process type and verified resource catalog. IsosUI owns the editor control.

## Input and output

`GET` uses the saved graph bytes, or the editable `0.1.0` initial draft when no graph exists. `POST` accepts `{"schema_version":1,"graph":{...}}` and never writes it. Both resolve the submitted graph version and exact registered type IDs without normalizing or migrating saved bytes. A valid `0.1.0` draft may have unavailable selections: the route still returns HTTP 200 so the editor can repair them. Unknown graph versions, unknown type identities or invalid selector declarations fail with HTTP 422 and a `data.diagnostics` entry: `unsupported_graph_version` at `/version`, `unsupported_node_type` at the affected `/node_type`, or P03 `node_option_selector_invalid` at the registered setting JSON Pointer. The selector error has `stage:"admission"` and never trusts an unrecognized provider/resource pair. Malformed API JSON or schema version fails with HTTP 400. A safe `1.0.0` graph retains the old three response collections; its exact registered legacy selectors may be shown read-only, but P03 does not invent a `0.1.0` MuJoCo catalog or update legacy bytes.

`data` retains `adapter_families`, `primitive_bindings`, and `targets` for existing clients, and adds `setting_options`, `graph_revision`, and `read_only`. `GET` returns `graph_revision` as the SHA-256 of exact saved bytes (or `""` when no graph exists) and `read_only` matching `GET /node-graph`; the client compares both GET revisions and discards a mismatched options response. `POST` has `graph_revision:null` because it receives a parsed draft rather than saved bytes, and `read_only:false` for a new `0.1.0` draft; the client accepts only the latest outstanding POST response for that draft. An applied safe legacy GET is `read_only:true`. The three old collections retain their existing shape and legacy meaning. In the new collection, group by the **pair** `(node_path, setting)`; there is exactly one group for each supported selector on each existing node. Groups sort ascending by UTF-8 `node_path`, then `setting`; candidates sort ascending by stable `value` (bytewise UTF-8), including the synthetic selected value. No duplicate group or option ID is permitted. The four-segment `node_path` is `core/layer/group/node`, with no leading slash. The public `setting` is a registered key such as `scene`, or the explicitly IsOS-owned nested key `adapter.settings.device_id` or `adapter.settings.simulator_node`. JSON Pointer paths in diagnostics use `/cores/<core>/layers/<layer>/groups/<group>/nodes/<node>` and RFC 6901 escaping for every segment.

| Field | JSON type / unit | Purpose and validation |
| --- | --- | --- |
| `graph_revision` | string or null / SHA-256 | Exact saved-byte revision for GET, empty string for missing graph, null for POST draft; correlate with `GET /node-graph`. |
| `read_only` | boolean / — | Saved graph editability for GET; POST target draft is false, safe legacy inspection is true. |
| `setting_options` | array / — | Complete sorted set of selector groups for this graph; `[]` when none. |
| `setting_options[].node_path` | string / four path segments | Exact instance identity; required, nonblank segments. |
| `setting_options[].setting` | string / dotted setting key | Exact registered or built-in selector identity; required. |
| `setting_options[].selected` | string or null / stable ID | Exact current graph value, or null when absent. Never silently replaced. |
| `setting_options[].options` | array / — | Sorted unique choices. One synthetic unavailable row is added if a nonblank saved ID is absent from the verified choices. |
| `options[].value` | string / stable ID | Exact graph value, nonblank and unique within the group. Package IDs are descriptor-scoped and never paths. |
| `options[].label` | string / display text | Nonblank operator label from the verified descriptor or an escaped, bounded saved-ID fallback. |
| `options[].description` | string / display text | Nonblank explanation from the verified descriptor or a bounded repair instruction. |
| `options[].available` | boolean / — | Whether this resource is eligible in the current draft context and exact pin; it does not imply that every other graph field is valid. |
| `options[].reason_code` | string or null / — | Stable P01/P02 code, or P03 `adapter_unavailable` for an uncompiled EOS adapter; null when available. |
| `options[].reason` | string or null / display text | Sanitized corrective action when unavailable; null when available. No local path, XML, environment value or receipt body. |

A P03 stable option ID is 1–128 ASCII bytes matching `^[a-z0-9]+(?:-[a-z0-9]+)*$`; provider-specific future IDs need an explicit contract extension. A nonblank selected value satisfying this grammar but missing from the verified catalog remains visible even if the package is absent, changed or has a legacy descriptor. A malformed selected value, including `/tmp/secret.xml`, fails HTTP 422 with `node_option_invalid_id` at its exact setting JSON Pointer and `stage:"admission"`; it is not echoed or made into a synthetic option. The synthetic row uses its exact selected `value`, an escaped and length-bounded label, `description:"Saved value is not in the verified catalog"`, `available:false`, and a reason code. Never use a filename, absolute path, executable path, `MUJOCO_ROOT` value, or package sidecar as an option ID. Missing or malformed selected values still fail graph validation; a non-string selected value is not coerced to an ID. Option rows may be cached only for the exact draft request that produced them. A client discards an older response after a newer draft request; a GET response belongs to its saved revision from `GET /node-graph`. No option response or client cache is accepted in Apply input.

## Providers and MuJoCo selectors

For a registered `Setting.selector`, IsOS dispatches only the declared `package`, `registry`, or `graph` provider and declared resource. A `package` selector requires its declared `package_from` (`node.package` or `node.adapter.package`) and resolves exactly that `{id,version}` through P01's verifier; it never scans for a latest or another installed release. An unrecognized provider/resource pair or invalid descriptor fails closed at the owning setting, rather than returning guessed options. Future asset selectors reuse this envelope. P03 does not execute `egia.tensor`, arbitrary model weights, or package code.

The verified `eos.process.mujoco@v0.1` process setting `scene` declares `{"provider":"package","resource":"scene","package_from":"node.package"}`. For a target `catalog_version:"0.1.0"` descriptor, its rows use `scenes[].id`, `label`, and `description`. The current exact values are `navigation` and `pick-place`. A legacy process `@v1.0` and complete historical descriptor retain their read-only behavior; a legacy descriptor cannot supply the target catalog or new preset. A partial descriptor produces P02 `mujoco_catalog_incomplete`, rather than silently falling back.

For generic EOS `eos.hardware.camera@v0.1`, `eos.hardware.base@v0.1`, and `eos.hardware.manipulator@v0.1` nodes with `adapter.type:"mujoco-v2"`, IsOS adds two built-in selector groups: `adapter.settings.device_id` and `adapter.settings.simulator_node`. The provider is the verified exact `node.adapter.package`, constrained to equal the referenced MuJoCo process `node.package`. The process reference comes from `adapter.settings.backend` and must identify the node also listed in `references`; `settings.scene` on that process controls scene membership. Candidate rows come from `device_catalog[]` with the matching hardware kind, use its stable `id`, `label`, and `description`, and are unavailable if their `scene_ids` excludes the current scene. The two groups expose the same candidate IDs; the editor sets both fields together. IsOS does not allow the external package to redefine those EOS types, their placement, adapter ABI or safety route. Apply rejects unequal `device_id` and `simulator_node` at the generic node's `/adapter/settings/device_id` pointer even if both IDs exist.

An exact pin that is missing, unverified or changed makes its choices unavailable; a changed linked payload takes P01 `package_changed` precedence. A missing selected scene or device appears as a synthetic unavailable row. Changing the scene or exact pin recomputes all dependent device rows from that draft. Missing host MuJoCo library makes catalog rows unavailable with `mujoco_library_unavailable`; it never turns a package path into a selector value. An EOS adapter that is not compiled remains unavailable with `reason_code:"adapter_unavailable"` and the existing sanitized adapter-family reason; it cannot Apply through a package claim. Apply reports `adapter_unavailable` at the generic node `/adapter/type`, `stage:"admission"`. Presentation may explain one blocking reason per row, in the order P01 receipt, P02 descriptor, scene/device membership, library, EOS adapter capability. Apply still reports the authoritative graph diagnostic.

## Apply and observable errors

`POST /node-options` does not require an expected saved revision. `PUT /node-graph` and CLI Apply do: compare the caller's expected SHA-256 of saved bytes inside the graph lock, then repeat P01 exact-pin verification, P02 catalog and selected-ID checks, generic adapter pair/reference checks, owner validation, and generated-config preflight before publication. Re-read the package under the final lock. A stale option response cannot authorize a former selection; GET clients compare `graph_revision` with their graph response and POST clients discard superseded responses; a stale graph revision is HTTP 409 with the existing `error:"node graph revision changed; reload before applying"`. A changed package or invalid selected value is HTTP 422 with `data.diagnostics:[{code,path,message,id,version,stage}]`. Validate returns the same diagnostic in its normal `valid:false` response. No rejection changes saved bytes, saved revision, active revision, or children. Run and Restart repeat the same package and selection checks before child replacement.

| Condition at direct link or Apply | Exact `code` / `stage` | Exact JSON Pointer |
| --- | --- | --- |
| Missing exact process pin `island/mujoco-sim@0.1.1` | `package_missing_file` / `manifest` | `/cores/eos/layers/process/groups/mujoco/nodes/simulator/package` |
| Changed linked process payload or scene | `package_changed` / `payload` | `/cores/eos/layers/process/groups/mujoco/nodes/simulator/package` |
| Partial target descriptor at direct package link | `mujoco_catalog_incomplete` / `descriptor` | `""` (no graph path; no receipt published) |
| Unknown selected scene after a stale option view | `mujoco_scene_unavailable` / `admission` | `/cores/eos/layers/process/groups/mujoco/nodes/simulator/settings/scene` |
| Unknown, wrong-kind or scene-ineligible device; unequal paired fields; different but independently verified adapter pin or backend reference | `mujoco_device_unavailable` / `admission` | `/cores/eos/layers/hardware/groups/<kind>/nodes/<id>/adapter/settings/device_id` |
| Malformed path-like selected scene ID | `node_option_invalid_id` / `admission` | `/cores/eos/layers/process/groups/mujoco/nodes/simulator/settings/scene` |
| Uncompiled generic EOS adapter | `adapter_unavailable` / `admission` | `/cores/eos/layers/hardware/groups/<kind>/nodes/<id>/adapter/type` |
| Missing host library | `mujoco_library_unavailable` / `admission` | `/cores/eos/layers/process/groups/mujoco/nodes/simulator/package` |

The adapter row uses the actual `kind` and instance `id`; the [P02 contract](mujoco-catalog.md#stable-diagnostics) freezes additional scene/profile/digest/device failures and [P01](package-verification.md) owns receipt diagnostics. If both a process and adapter pin are damaged, P01's canonical first pin wins; no options API result may mask its failure. The [P03 fixtures](../../../tests/fixtures/node_options/README.md) freeze positive rows, stale and negative scenarios, exact codes/paths/stages and no-write invariants.
