# IsOS guide

IsOS is the local owner of the saved graph, backend packages, workbench API, and direct-child process manager. It also manages explicitly started model-like services outside the graph. The first integrated target is `island/mujoco-sim@0.1.1`. Read in first-use order: [start and inspect logs](usage/get-started.md), [0.x architecture](design/system.md), [implementation milestones](maintenance/roadmap.md), [node catalog](layers/README.md), [graph fields and compatibility](interfaces/node-graph.md), [package operations](usage/packages.md), [release contract](interfaces/releases.md), [verified package admission](interfaces/package-verification.md), [local API and selectors](interfaces/local-api.md), [configuration and versions](interfaces/configuration.md), [shared deployment events](interfaces/events.md), [current-run log cursors](interfaces/log-cursors.md), [independent services](interfaces/services.md), then [source layout](develop/source-layout.md) and [development checks](develop/backend.md).

The saved `.nodes.json` graph is the only deployment path. An optional user unit can run product `isos serve`. **Current binaries write `0.1.0`, read safe `1.0.0` and `0.1.0`, and offer explicit revision-checked migration.** Node type versions are independent. EOS starts MuJoCo from package paths verified by IsOS and connects its adapters to it; EGIA common nodes remain design-only today. The P01 [verified package contract](interfaces/package-verification.md) describes the next integrity boundary. Later target behavior is labeled in each contract.

The R03 [managed control-grant contract](interfaces/control-grants.md) and [launch design](design/control-grants.md) record the qualified IsOS issuance and EOS handoff after merged owner PRs and a clean-home replay. The broader I4 lifecycle gate and R05/R06 physical simulator qualification remain open.

R04's [verified native-skill selection contract](interfaces/skill-selection.md) and [transaction design](design/skill-selection.md) define the exact package/library handoff to the EOS worker. The IsOS implementation candidate admits that selection; independent review and cross-owner qualification remain open.
