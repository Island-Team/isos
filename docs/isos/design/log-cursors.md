# P07 current-run cursor design

[中文](../../../docs_cn/isos/design/log-cursors_cn.md) · [Owner interface](../interfaces/log-cursors.md) · [P06 event design](events.md) · [Fixtures](../../../tests/fixtures/log_cursors/README.md)

**Implemented in P07.** The [owner interface](../interfaces/log-cursors.md) freezes the API. P07 extends `src/runtime/log_store.rs::read_filtered`, `src/app/http.rs::logs`, `src/app/cli/mod.rs::Logs`, `src/app/entry.rs` and manager status after P06 event admission. It does not change the legacy inode/offset cursor path. IsosUI uses the opt-in view and must treat `process-status` as live state authority.

## State and append order

`LogStore` currently rotates each source and `events.log` by rename, then reads only the newest file using an inode/birth-time/offset cursor. It cannot continue a rotated backup or distinguish an older run. Add a private `cursor-state.json` below the same deployment log directory with schema version, deployment identity, current manager session, last admitted run ID, two pinned sanitized anchors, segment generations and bounded ingest/write-loss counters. The file and temporary replacement are `0600`, parent directory `0700`; publish by write, fsync, rename and parent fsync. Fresh deployment initialization durably records `never_run` before P07 serves manager scope; an absent or malformed file on an existing deployment is not a never-run claim. Any invalid, symlinked or mismatched state fails closed. Retained starts do not prove that no later run was admitted before its starting append failed. An invalid state record therefore cannot recover a last run from `events.log`; set `process-status.run_id_state:unavailable` and return HTTP 503 `log_scope_unavailable` at `/scope` from `view=current`; never invent manager scope. This state is not a source of child authority. Do not put executable paths, raw line bytes, secrets or graph contents in the state.

Authenticate the complete private state with a separate stable `scope-key` (`0600`), created and parent-fsynced before the first state publication. Each state replacement updates its scope seal before the admission barrier releases a child. Never recreate a missing key for an existing state: missing or mismatched proof makes `run_id_state` unavailable, and an invalid existing state cannot enter the P06 upgrade path. Only a directory missing both state and scope key may enter that path. This proof is independent of the rotatable `cursor-key`, so a cursor-key change invalidates page tokens and may lose anchor proof without changing a proven last-run ID.

P06 currently emits `deployment_preflight_failed` from both Validate and Apply. Pass a private call-site operation marker to P07 anchor capture: only the Apply call site is eligible, while a typed package failure is eligible wherever preflight occurs. The marker is not inferred from `message` or `event_code` and need not be a new P06 wire field. On the first such `error` for the current manager session, persist a copy of the already sanitized P06 event as the manager anchor before returning the public failure. The selected child collector authenticates role/run/code before it may choose a run anchor; the first owner-ready code or accepted `error` event for the admitted run is copied before collection acknowledgment. A child event with an untrusted source or the schema-1 compatibility socket is never eligible. The anchor copy is a retained record, not a second producer or a fabricated event. If anchor persistence fails, set a bounded loss counter and report `log_anchor_unavailable`; do not claim it was durably captured. The normal unified/source append may then proceed or fail independently. Preserve the prior run anchor until a new run is admitted and its scope ID is durably published; a failed Restart preflight keeps the old run. Admission has an explicit barrier after all preflight and safe replacement stop/reap: allocate the candidate run ID, atomically write the new last-run ID plus `pending` anchor state, fsync file and parent, then spawn the first child. Do not emit or spawn a child on publication failure. Return `log_scope_publish_failed` at `/run_id` and preserve the old durable scope when writing failed before rename. If rename succeeded but parent fsync failed, return the same typed error and do not spawn; on recovery, a surviving new record is treated as admitted and gets failed status; without an accepted failure event its anchor becomes `unavailable` with `log_anchor_unavailable`, never silently reverted or left permanently pending. A crash after successful publication but before spawn likewise leaves an admitted run with no fabricated ready event; recovery reports failure/status independently and marks the anchor `unavailable` if no accepted failure event exists. Candidate and recovery runs use distinct IDs from P06.

The scope selector reads the last admitted run identity, not PID or `active_revision`. Its persisted value remains through stopped/failed and manager restart, and advances only at admitted replacement. Before the first admitted run it uses the current manager session. A new manager session changes manager scope before any run; clients holding old manager cursors receive `log_run_changed`. In a run with no ready/failure yet, return a pending anchor and no lines; the poll token remains bound to the run and becomes an anchor-resuming token when one arrives. A torn or invalid identity record fails closed. A retained P06 stream cannot rule out a later admission whose starting append failed. Candidate lines and pinned anchors still require complete P06 envelope and accepted-position checks; never select an event of another run or synthesize one from process state. A valid last-run record is authoritative for run identity even if its anchor event has rotated out: restore the pinned copy and keep the stopped/failed scope. If the identity is known but the anchor is unrecoverable, return `anchor.state:unavailable` plus `log_anchor_unavailable`. If identity itself cannot be proven, return HTTP 503 `log_scope_unavailable` rather than a 200 manager page; `process-status` keeps live fields and marks `run_id_state:unavailable`.

## Read path

For `view=current`, first choose the scope and pinned anchor. Then decode and authenticate a bounded `lc1.` token against deployment, scope kind/ID and normalized filters. A malformed token or changed filter returns typed HTTP 400 without echoing it. Invalid `node_path` and `correlation_id` query values return `log_node_path_invalid` at `/query/node_path` and `log_correlation_id_invalid` at `/query/correlation_id` respectively, before cursor matching. An unavailable scope returns HTTP 503 `log_scope_unavailable` at `/scope`. A valid old-scope token receives HTTP 200 with `log_run_changed`, new anchor and new cursor. Resolve the token's segment generation and offset against `events.log.<N>` and `events.log`; read retained segments oldest to newest, at most 64 KiB of raw log bytes and 200 matching records per call. A segment still present crosses rotation with `rotated:true` and no gap. An expired segment rebases to the earliest retained record strictly after the anchor, sets `rotated:true` and reports `log_cursor_expired` with unknown count unless a durable sequence proves an exact count. Do not silently start at newest file. Scan-bound empty pages advance the cursor over nonmatching events.

Every candidate line is parsed as a P06 stored event. Check its `run_id` against the selected scope first; discard other runs. The anchor is out-of-band and returned without source, minimum level, node or correlation filters. For subsequent lines apply those four filters conjunctively; no filter changes the anchor choice. A cursor is generated from the position after the last scanned record, not after the last displayed record. Store the anchor’s accepted segment generation/offset alongside its sanitized copy. Compare that position to each candidate; a later event with the same `event_code` is a separate line and must not be discarded. Use a durable per-deployment MAC key in a separate private `cursor-key` file (`0600`) for token integrity and authenticated version/deployment/scope/filter/segment/offset claims; never expose the decoded claims as a public format. A key rotation or unreadable key invalidates old tokens with `log_cursor_invalid` while preserving a separately valid durable run ID. When the old anchor seal cannot be proven, the new page returns that run with an unavailable anchor and a collector gap of unknown count. Replace an unusable private key atomically for fresh tokens.

`log_collector_gap` comes from P06's bounded rejected/dropped/write-failure counters, not inferred solely from a time jump or inode change. Return a known nonnegative count when durable; otherwise null. Present diagnostics in stable order: run change, expired segment, collector gap, anchor unavailable. Status remains authoritative if there is no ready/failure event because a child was killed before it could emit. The UI should render the pinned anchor ahead of filtered lines, show the gap, reset visible lines when scope changes, and keep Stop and current status visible. After Stop, the last run's terminal event remains in the current view; do not switch to manager session because processes are gone.
