# P01 package verification design

[中文](../../../docs_cn/isos/design/package-verification_cn.md)

**P01 implementation.** The [verified package contract](../interfaces/package-verification.md) owns the receipt fields, commands and failures. This page explains the verifier and transaction. P02 adds scene/device choice semantics.

## Publication transaction

Take the package lock, validate an exact release and platform asset, then create a private sibling staging directory. For an archive, stream the asset into staging with the selected asset's size and SHA-256 limit, reject unsafe or repeated entries, and set owner-only permissions. For a link, validate a compatible host asset and check every source and manifest path component without following a symlink. Run one payload verifier over both roots: validate the backend descriptor's identity/protocol, bounded transitive scene XML file references (including contained `..` traversal) and all other referenced contained regular files, executable bit, declared adapter digests, activation template sources and package contribution structure. Compute a deterministic whole-tree digest and generate the sidecar solely from the accepted release object. Write the release snapshot, sidecar and receipt with separate digests, fsync their files and staging directory, then atomically rename staging to the absent exact-version target and fsync its parent. Any failure before rename removes staging; no graph or process handle is acquired by package publication.

The linked source stays at its original path for developer builds. The published receipt freezes a content digest and canonical root, rather than pretending the external tree is immutable. Revalidating a changed link returns a stable `package_changed` diagnostic; relinking is a deliberate replacement operation after reference checks. Installed payloads also get a tree digest, so mutation after extraction is detected. The content walk rejects symlinks and special files in all directories, verifies path components before open, and compares file identity around streaming reads to reduce rename races. The unit suite covers a symlink inserted after link. This is local integrity, not a claim of protection against the owner replacing every metadata file.

## Admission order

Before selecting a sidecar, collect exact pins from all supported graph shapes once and reject malformed pairs. For each referenced pin, check the store path and verifier-owned metadata without following symlinks, then rederive all three digests, verify the descriptor/reference closure, and return a verified handle containing canonical payload root, accepted release and generated sidecar path. Pass only those handles to core setup, node-set composition, backend discovery and EOS launch projection. Apply, migration commit, Run and Restart invoke this before publication or spawn; legacy changed Apply repeats verification while holding the final publication lock; Validate and preview may return the same package diagnostics without mutation. Package listing scans store entries but marks malformed or legacy receipts unavailable rather than making them runtime inputs. A global catalog can inspect installed packages, yet a graph's sidecars must be exactly its verified pin set.

The existing backend fingerprint can remain a launch input for selected scene content, but cannot replace the release/payload/sidecar proof. P02 adds semantic checks for stable scene/device IDs, the MuJoCo runtime library and selector descriptions. P03 resolves setting options; neither changes P01's exact-pin integrity rule.

## Evidence

The [frozen P01 cases](../../../tests/fixtures/package_verification/README.md) define the acceptance matrix. The Rust unit suite covers tree hashing, exact pins, wrong-host links, missing and escaping nested scene assets, payload/release/sidecar tampering, and symlinked source, metadata and store paths. The seven-case clean-home CLI/HTTP replay covers verified link and archive installation, digest rejection, collision, exact pin mismatch, both graph versions, Apply/Run refusal after tampering, unchanged revisions, unavailable legacy/corrupt listing, and sanitized diagnostics. The reproducible gates passed: `cargo fmt --all -- --check`, `cargo clippy --all-targets --no-default-features -- -D warnings`, `cargo test --no-default-features` (117 tests), `cargo build --no-default-features`, and `python3 tests/package_verification_cli.py` (7 tests) with EOS's `aether-profile` built. Full output is kept locally under `logs/test/20261101-p01-review-fixes/`. This is integrity and admission evidence; P02 owns MuJoCo device semantics and P04 owns generated configuration preflight.
