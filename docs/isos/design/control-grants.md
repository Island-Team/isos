# R03 launch grant handoff design

[中文](../../../docs_cn/isos/design/control-grants_cn.md) · [Owner contract](../interfaces/control-grants.md) · [Cases](../../../tests/fixtures/control_grants/README.md)

**Target design; not implemented.** R03 makes IsOS the issuer for EOS's managed Dispatcher authority. The issuer is part of the manager's Run/Restart transaction, not Apply or the immutable P04 generation. The saved graph determines the exact revision and recipients; it contains no credential field. The selected P04 leaf provides the verified EOS projection, while a separate private runtime bundle binds the run and its revision.

## Transaction

1. Under the deployment lock, reread saved bytes and verify the selected schema-2 leaf, exact package pins, owner render, selected binaries, reader features and all `env_from` values. Reject an old graph, missing recipient or changed generation before any active child stops. Use the final saved-byte SHA-256 as the candidate `active_revision`.
2. Allocate a new deployment `run_id` only when Start creates a run or Restart replaces it. Generate both grants independently with the OS CSPRNG. Create a fresh private run directory and three files with no-follow/exclusive creation, restrictive modes, exact bounds, file and directory fsync. Bind the verifier to that run ID and revision. Do not add the bundle to `manifest.json` or its generation digest; a same-revision Restart must rotate grants without changing Apply output.
3. Only after the bundle is durable may IsOS stop old children. Start candidate children in dependency order, passing the verifier path to EOS, EGIA grant path to EGIA and operator grant path to bridge. Remove all three reserved names from inherited and authored child environments first. An unselected process gets none. The existing `ISOS_RUN_ID`/`--run-id` and effective `--profile` inputs must match the verifier; the child may not choose another graph or run.
4. Wait for EOS owner readiness beyond TCP bind: verified manifest and grants, complete discovery and writable admission status. EGIA and bridge readiness depend on their allowed EOS path. Publish `deployment_ready` only after the dependency chain passes. On child failure, stop candidate dependents before providers, leave a terminal candidate run event, reap processes, then retire its bundle.
5. On explicit Restart, retire the previous bundle only after previous children have been stopped and reaped. If replacement fails, recovery of old specifications uses a **fresh** run ID and bundle; failure to issue or deliver that recovery bundle leaves the deployment degraded. Never relaunch old specs under a prior run credential. On automatic child restart within one active run, retain the same bundle and verify its regular files before reuse; this preserves operation lookup after a lost response. Stop retires the bundle after reaping all its recipients. On manager process restart, an orphaned bundle is never selected for a new run; cleanup may remove it only after confirming no associated child is alive.

The run bundle is an authority capability, so a symlinked ancestor, wrong UID, loose mode, special file, duplicate destination, truncated hex, missing newline, unexpected field, changed digest, run mismatch or revision mismatch is a stop-before-ready error. File descriptors and path reads use no-follow checks; permissions are checked again at the recipient boundary. A candidate bundle prepared before stop is not attached to old children. Cleanup errors are reported in sanitized local diagnostics and do not turn an unverified child into ready. File contents, grant digests, bearer metadata and typed movement arguments never enter events, status or a graph error body.

## Integration seams and tests

The current `Supervisor` stores one `run_id`, passes `--run-id` to selected EOS children and `ISOS_RUN_ID` to EGIA, and retains it across automatic child restarts. `restart_processes_with_plan` allocates a candidate run; on failed replacement it allocates another recovery run. Implement the grant bundle as a run-owned object retained with the supervisor and passed to `spawn` through a private launch plan. Do not represent it as graph `settings.env`, `env_from` or a generated file. `generated_v2::selected_root` already verifies the immutable P04 leaf and should remain the source of selected revision/profile bytes. Preflight must happen before `managers.remove(name)` and child stop. The current first-use status exposes saved and active revisions and run ID; this remains the observable identity, without credential fields.

The fixture matrix covers issuance, exact role delivery, same-run reuse, explicit rotation, failed-restart recovery rotation, rejection before stop, filesystem attacks and sanitized errors. Unit tests can use deterministic injected random bytes only in test builds; production reads the OS CSPRNG. An integration stub records only which reserved environment names it received, not their values. EOS fixture replay proves verifier/run/revision checks and the method matrix; IsOS replay proves issuance and process delivery. R07 later proves browser bridge result follow-up, and R05/R06 prove physical fencing and simulator stop order.
