# R06 dependent stop design

[中文](../../../docs_cn/isos/design/dependent-stop_cn.md) · [Owner contract](../interfaces/dependent-stop.md) · [Frozen cases](../../../tests/fixtures/dependent_stop/README.md) · [First use](../usage/get-started.md#r06-dependent-stop-target)

**Implementation under qualification.** The [owner contract](../interfaces/dependent-stop.md) defines API fields, units, terminal reasons and event codes. This page explains how the manager will make one stop decision across its CLI, API, Ctrl+C, Restart, rollback, provider loss and shutdown paths. EOS and MuJoCo retain their own actuator and simulator boundaries.

## Existing seam and change

`Supervisor::stop` currently drains reverse launch order, calls `terminate` per direct child with a fixed two-second SIGTERM grace, retires the control-grant bundle, and returns only process IDs. `terminate` returns no exit, process-group or physical-stop result. Restart and provider-loss paths also call it without a terminal outcome. `Drop` calls it again, and a stopped-event append occurs after reap. R06 replaces these fragmented calls with one idempotent stop operation that carries a monotonic deadline, a run-bound outcome and a deterministic reverse dependency plan. It must still use the selected child handle and recorded process group; no status PID or graph command becomes a signal target.

## Stop state machine

For each admitted run, retain `Running → Stopping → ConfirmedStopped | UnknownStopped`. Stop atomically closes new manager Start/Restart admission for that deployment, snapshots selected child identities, dependency graph, run ID and grants, and **durably writes an unknown stop intent before normal graceful signaling**. If that bounded write fails or stalls, emergency signaling proceeds with an irrevocably unknown result. A concurrent Stop joins that state; only its owner sends signals. The initiating caller supplies one correlation ID for all stop events. Readiness, automatic child restart and new grants cannot race a stopping run. `Drop` can perform only bounded best-effort cleanup if a terminal outcome has not been published; it cannot replace unknown with confirmed. A crash after intent but before or during signaling recovers as unknown; no saved PID is trusted for a new signal.

Build a reverse topological order from the **active** admitted specs rather than assuming `self.order` remains complete after a crash. For independent peers, break ties by reverse launch index. Stop all dependents before their providers. Hold the EOS provider until all other selected graph children have either exited or consumed their non-EOS budget. If one dependent ignores TERM, issue KILL to its recorded group and proceed within the same global deadline; do not strand EOS's reserved window. A provider's unexpected death triggers the same plan for remaining dependents and an unknown terminal outcome; automatic restart is blocked until that outcome is resolved. Each child record stores observed exit status, group-drain result, signal failures and owner proof; select one fixed reason by priority and record every child once.

At spawn, record the direct-child leader PID, session and optional pidfd while holding the child. Poll exit with Linux `waitid(..., WNOWAIT)`, which observes status **without reaping** and keeps the leader PID allocated. `Child::try_wait` and `wait` are forbidden until the last planned group signal. Before `kill(-pgid, SIGTERM|SIGKILL)`, compare the held unreaped leader with its recorded `/proc/<pid>/stat` start ticks, PID/PGID and session; never signal a group after its leader was reaped or when identity is ambiguous. A pidfd identifies the leader but does not authorize a negative-PGID signal after reap. A direct child exiting zero while a same-group descendant remains live does not prove the group drained. `ESRCH` from a verified group-liveness check means empty; `EPERM` or ambiguous membership means unknown. Existing status/provider polling must use the same nonreaping path. If a legacy path already reaped the leader, fail closed without signaling a possibly reused PGID. After the last safe signal, reap the direct child; if descendants cannot be proved absent, report unknown. A forced kill remains unknown even when reap succeeds. Attempt grant retirement after bounded group cleanup, including when a child remains unresolved; such a run is already unknown and cannot authorize reuse. Failed or unresolved retirement is visible and cannot authorize reuse.

Compute `deadline = stop_start + stop_timeout_ms` and `cleanup_at = deadline - 2,000 ms` from one monotonic clock. No graceful wait may pass `cleanup_at`; at that instant or earlier, safely KILL remaining owned groups and mark them unknown. Poll direct-child reap without blocking for at most 1,500 ms, leaving at least 500 ms for the **live** finalization fence and response. The stop owner and deadline timer serialize on one in-memory state cell keyed by run ID. Under the fence, the owner checks the monotonic clock and every child-group and EOS proof, then atomically selects and publishes the same value to shared status and a bounded nonblocking response queue. Confirmed publication must complete strictly before deadline; if the queue cannot accept it, publish unknown. At or after deadline, the timer publishes unknown, including equality. Later OS transport flushing cannot change the queued value. Once published, the cell is immutable for all callers; neither a filesystem worker nor a log collector may write it. No worker ever publishes durable confirmed, so a stalled rename or parent fsync of the pre-signal unknown intent can complete after the caller returns unknown without changing the safety outcome. The manager retains unreaped handles for later bounded cleanup while alive; after shutdown it never trusts a recorded PGID for another signal. Logging is outside the stop deadline's critical path.

The EOS-specific confirmation step reads the selected child’s raw stdout pipe through a dedicated strict parser before P06 log normalization. Its sole accepted frame is one newline-terminated, at-most-4096-byte schema-1 `eos_terminal_stop` object. Bind `run_id`, `eos_pid`, `active_revision`, canonical `backend_node`, selected `parts` and the pipe itself to the admitted run. Reject duplicate/unknown/missing keys, partial/oversized/second/late lines and wrong-pipe frames before they enter the bounded receipt channel. EOS closes the inherited stdout writer in MuJoCo and helpers; IsOS requires EOF after the one line and EOS exit, but never waits past EOS grace for it. Validate backend PID/PGID equality, generation/epoch shape, four shutdown facts, all selected part outcomes and fixed reason codes against the [owner contract](../interfaces/dependent-stop.md). EOS alone proves the nested MuJoCo group drain and dual physical stop; IsOS verifies its structured assertion and independently verifies its own EOS group drain, zero exit and leader reap before the live fence. EOS’s `managed-stop-v1` capability token is only an early support check. Its 15,000 ms hard shutdown bound fits the default 20,000 ms IsOS grace; a configured shorter grace or late receipt produces unknown. An EOS unknown receipt or nonzero exit remains unknown even if other facts appear positive. On receipt processing, acquire the run-scoped finalization fence and check the global deadline first: if it has arrived and the cell is pending, publish `stop_deadline_exceeded`. Otherwise, a receipt at/after EOS grace is `eos_receipt_late`, then the selected-pipe parser checks validity. A wrong run ID on that selected pipe is invalid; a frame on another pipe is ignored and leaves the selected pipe missing. Earlier published terminal reasons never change.

## Lifecycle call sites

Explicit Stop and attached Ctrl+C share the result. Manager shutdown stops every deployment before independent services and listener teardown; if any deployment is unknown, it retains a durable unknown intent and exits nonzero where a process exit is available. A normal shutdown cannot emit `deployment_stopped` for a run that was force-killed. Restart completes P04/P05/package/grant candidate preflight first, then stops the old run. If old stop is unknown, it must not launch the candidate or a restored old generation and returns the typed terminal outcome; the candidate grant is retired. If candidate startup fails after a confirmed old stop, stop its partial process groups with the same primitive, publish `deployment_failed` for that candidate, then restore old specs only with a fresh run and grants. If rollback stop is unknown, do not restore. Provider loss stops dependents in reverse order, marks the old run unknown and suppresses automatic recovery until the owner can prove a safe fence. These rules prevent an uncertain movement from being replayed by process restart.

The current P06 and P07 stores keep the first ready/failure anchor and last admitted run scope. After P07 publishes a new run and before first spawn, IsOS atomically creates a **new run-specific** stop-state file with `phase:running,outcome:null`; the old run file is never overwritten. A crash or failed write between P07 publication and this creation leaves the new run unknown and unlaunchable. Before normal graceful signaling, Stop atomically writes and fsyncs `phase:stopping,outcome:unknown` in the same run file. That unknown intent is Stop's single durable commit point. Intent publication has a bounded 500 ms allowance inside the stop budget; if it fails or stalls, a late worker may write only unknown to that run file, while IsOS proceeds with best-effort emergency signals and a live unknown result. A manager restart treats any last-run `running`, `stopping`, missing or invalid file as unknown because the old child identity hold cannot be restored. It also treats a previously live confirmed Stop as unknown: no durable confirmed record exists, and a retained `deployment_stopped` log line cannot authorize launch. After physical proof, only the live finalization fence may report confirmed. A confirmed event is queued only after that fence; event write failure increments the bounded log counter and cannot change the terminal value. Errors use fixed reasons without child output or grant values. While stopping, process-status reports `state:"stopping"`, current run and child snapshots; after unknown it reports `state:"degraded"` even with no child. Recovery compares deployment/run binding to P07 last-run identity and never infers confirmation from logs.
