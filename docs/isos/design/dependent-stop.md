# R06 dependent stop design

[中文](../../../docs_cn/isos/design/dependent-stop_cn.md) · [Owner contract](../interfaces/dependent-stop.md) · [Frozen cases](../../../tests/fixtures/dependent_stop/README.md) · [First use](../usage/get-started.md#r06-dependent-stop-target)

**Target design — not implemented.** The [owner contract](../interfaces/dependent-stop.md) defines API fields, units, terminal reasons and event codes. This page explains how the manager will make one stop decision across its CLI, API, Ctrl+C, Restart, rollback, provider loss and shutdown paths. EOS and MuJoCo retain their own actuator and simulator boundaries.

## Existing seam and change

`Supervisor::stop` currently drains reverse launch order, calls `terminate` per direct child with a fixed two-second SIGTERM grace, retires the control-grant bundle, and returns only process IDs. `terminate` returns no exit, process-group or physical-stop result. Restart and provider-loss paths also call it without a terminal outcome. `Drop` calls it again, and a stopped-event append occurs after reap. R06 replaces these fragmented calls with one idempotent stop operation that carries a monotonic deadline, a run-bound outcome and a deterministic reverse dependency plan. It must still use the selected child handle and recorded process group; no status PID or graph command becomes a signal target.

## Stop state machine

For each admitted run, retain `Running → Stopping → ConfirmedStopped | UnknownStopped`. Stop atomically closes new manager Start/Restart admission for that deployment, snapshots selected child identities, dependency graph, run ID and grants, and **durably writes an unknown stop intent before any signal**. A concurrent Stop joins that state; only its owner sends signals. The initiating caller supplies one correlation ID for all stop events. Readiness, automatic child restart and new grants cannot race a stopping run. `Drop` can perform only bounded best-effort cleanup if a terminal outcome has not been published; it cannot replace unknown with confirmed. A crash after intent but before or during signaling recovers as unknown; no saved PID is trusted for a new signal.

Build a reverse topological order from the **active** admitted specs rather than assuming `self.order` remains complete after a crash. For independent peers, break ties by reverse launch index. Stop all dependents before their providers. Hold the EOS provider until all other selected graph children have either exited or consumed their non-EOS budget. If one dependent ignores TERM, issue KILL to its recorded group and proceed within the same global deadline; do not strand EOS's reserved window. A provider's unexpected death triggers the same plan for remaining dependents and an unknown terminal outcome; automatic restart is blocked until that outcome is resolved. Each child record stores observed exit status, group-drain result, signal failures and owner proof; select one fixed reason by priority and record every child once.

At spawn, record the direct-child leader PID, session and optional pidfd while holding the child. Poll exit with Linux `waitid(..., WNOWAIT)`, which observes status **without reaping** and keeps the leader PID allocated. `Child::try_wait` and `wait` are forbidden until the last planned group signal. Before `kill(-pgid, SIGTERM|SIGKILL)`, compare the held unreaped leader with its recorded `/proc/<pid>/stat` start ticks, PID/PGID and session; never signal a group after its leader was reaped or when identity is ambiguous. A pidfd identifies the leader but does not authorize a negative-PGID signal after reap. A direct child exiting zero while a same-group descendant remains live does not prove the group drained. `ESRCH` from a verified group-liveness check means empty; `EPERM` or ambiguous membership means unknown. Existing status/provider polling must use the same nonreaping path. If a legacy path already reaped the leader, fail closed without signaling a possibly reused PGID. After the last safe signal, reap the direct child; if descendants cannot be proved absent, report unknown. A forced kill remains unknown even when reap succeeds. Retire grants only after direct children are reaped or conclusively gone; failed retirement is visible and cannot authorize reuse.

Compute `deadline = stop_start + stop_timeout_ms` and `cleanup_at = deadline - 2,000 ms` from one monotonic clock. No graceful wait may pass `cleanup_at`; at that instant or earlier, safely KILL remaining owned groups and mark them unknown. Poll direct-child reap without blocking for at most 1,500 ms, leaving at least 500 ms for durable terminal publication. A final-state worker may fsync a temporary file off the manager request path, but must recheck deadline and run/phase under the state lock before rename. If it finishes after deadline, it discards the temporary file; the pre-signal durable unknown intent remains. If final persistence is incomplete at the deadline, the caller returns unknown and no background completion may later turn it confirmed. The manager retains unreaped handles for later bounded cleanup while alive; after shutdown it never trusts a recorded PGID for another signal. Logging is outside the stop deadline's critical path.

The EOS-specific confirmation step waits for the **reviewed EOS R06 machine-checkable terminal receipt** for this run and observed child PID. It must represent both base and arm stop/fence outcomes, simulator reap and socket cleanup; a generic `eos_stopped` line or process exit 0 is insufficient. IsOS checks the receipt against EOS exit and group drain, then records `confirmed` only if all agree. EOS may emit a separate error or unknown receipt while still exiting normally; IsOS preserves unknown. The exact receipt transport, fields and maximum EOS graceful bound remain an owner-contract question for independent design review. Until resolved, the IsOS code path must fail closed with `eos_receipt_missing`.

## Lifecycle call sites

Explicit Stop and attached Ctrl+C share the result. Manager shutdown stops every deployment before independent services and listener teardown; if any deployment is unknown, it retains a durable unknown result and exits nonzero where a process exit is available. A normal shutdown cannot emit `deployment_stopped` for a run that was force-killed. Restart completes P04/P05/package/grant candidate preflight first, then stops the old run. If old stop is unknown, it must not launch the candidate or a restored old generation and returns the typed terminal outcome; the candidate grant is retired. If candidate startup fails after a confirmed old stop, stop its partial process groups with the same primitive, publish `deployment_failed` for that candidate, then restore old specs only with a fresh run and grants. If rollback stop is unknown, do not restore. Provider loss stops dependents in reverse order, marks the old run unknown and suppresses automatic recovery until the owner can prove a safe fence. These rules prevent an uncertain movement from being replayed by process restart.

The current P06 and P07 stores keep the first ready/failure anchor and last admitted run scope. After P07 publishes a new run and before first spawn, IsOS atomically replaces its private stop-state record with that run's `phase:running,outcome:null`. A crash or failed write between publication and reset leaves a run mismatch; recovery treats the new run as unknown and refuses launch. Before signaling, stop persists `phase:stopping,outcome:unknown` for the same run. Intent publication has a bounded 500 ms allowance inside the overall stop budget. If its worker fails or stalls, cancel any late commit, downgrade the result and issue best-effort emergency signals; on manager restart, any nonterminal last-run state, including `running`, recovers unknown because the old child identity hold cannot be reattached. Once children are handled, IsOS may publish `phase:terminal` and one terminal deployment event. Event write failure increments the bounded log counter; live status and terminal state remain authoritative. Errors use fixed reasons without child output or grant values. While stopping, process-status reports `state:"stopping"`, current run and child snapshots; after unknown it reports `state:"degraded"` even with no child. Recovery compares deployment/run binding to P07 last-run identity and never infers confirmation from logs.

## Verification plan

Unit tests use a fake monotonic clock, injected signal/reap seams and a stub EOS terminal receipt. They exercise reverse dependency order, deterministic peer order, simultaneous Stop joining, unexpected provider death, TERM grace, KILL at `cleanup_at`, bounded reap/publication, group descendant survival, leader-reap/PGID-reuse race, stale run receipt, crash after durable intent, crash between P07 publication and new-run reset, failed persistence and log writer outage. Boundary tests launch actual process groups with a child that ignores TERM, a descendant that outlives its parent, selected EOS and MuJoCo for both scenes, unavailable GUI, simulator crash and socket cleanup. Restart tests inject candidate failure and rollback failure, then compare old/new run IDs, grants and readiness events. Assert that no candidate starts after an unknown old stop and that no unknown result is reported as `deployment_stopped`.

The independent owner review must first settle EOS's terminal receipt identity and graceful bound. Implementation then runs IsOS Cargo fmt, strict Clippy, test and build; the [fixture checker](../../../tests/fixtures/dependent_stop/check_cases.py); a clean-home CLI/API/Ctrl+C/manager-shutdown replay; and EOS/MuJoCo R06 boundary tests. Save complete output in ignored `logs/test/<run-id>/`, record exact commands and results in this page, and request a second independent implementation review before PR merge. R06 cannot close merely because the stub tests pass.
