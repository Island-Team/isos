# P06 deployment event design

[中文](../../../docs_cn/isos/design/events_cn.md) · [Owner contract](../interfaces/events.md) · [First use](../usage/get-started.md)

**P06 implementation.** The [event interface](../interfaces/events.md) owns the JSONL fields, limits and lifecycle rules. `LogStore` creates private rotating source files and `events.log`; `Supervisor` binds selected child role, run and observed PID before admitting a structured stderr event. The schema-1 legacy append path is normalized to an untrusted manager event. P07 adds cursor retention across rotation.

## Admission path

The API, CLI and Unix manager select one deployment and request correlation before work. Prelaunch package and graph failures use the current manager-session ID even when an earlier deployment is active; this prevents an Apply failure from appearing to belong to an unrelated running revision. After all P04/P05 preflight and secret resolution pass, Start allocates a deployment-run ID and records it with the supervisor before the first child starts. Restart creates a candidate run only when it reaches replacement; a failed preflight keeps the old active run. A failed replacement becomes terminal on its candidate run, and a restored prior specification receives a distinct recovery run. Idempotent Start returns the existing run. The manager passes the ID to EOS and EGIA as defined in the owner contract and retains it for stop, child recovery and status. One run can contain several automatically restarted child PIDs; correlation IDs distinguish attempts.

`LogStore` accepts a bounded event object after checking its envelope and safe fields. The manager's own call sites emit fixed event codes and safe message templates with typed metadata; they never format an arbitrary error chain into a message. P01 receipt logging rechecks the requested `{id,version}` and copies only the available digest/commit fields from the verified receipt. A failed package verification with no trustworthy receipt emits null provenance instead of reading a possibly altered file. Manager Run/Restart preflight and HTTP graph Validate/Apply failures emit one fixed `deployment_preflight_failed` event before their public reply. Known structured diagnostics contribute their code and bounded graph pointer; unknown errors contribute no raw error text. The schema-1 `log_append` socket only checks peer UID, so it cannot authenticate a caller's claimed child role. The compatibility adapter validates the old request and preserves `accepted:true` but replaces its source, code and message with the fixed `legacy_external` manager event defined in the owner contract. It does not assign an active deployment run or emit a child-ready event.

The `Supervisor` knows the selected child role, PID, active run and authorized node paths. It reads bounded stderr lines, strictly parses one JSON object without duplicate keys, verifies the child's claimed source/core/run against its role and active run, validates that an EOS child names only an admitted EOS node and an EGIA child only an admitted EGIA node, and applies code-specific safe-field rules. The selected EOS runtime may claim `source:eos`, its HTTP bridge `source:bridge`, its config server `source:config`, and the selected EGIA child `source:egia`; raw MuJoCo diagnostics remain under the EOS owner directory. A child cannot claim another role. The compiled IsOS `event_policy` table pins each selected role's exact codes, typed fields, severity and suppression class against reviewed owner P06 contracts. This includes EOS runtime-only `eos_events_suppressed`; IsOS alone emits shared `events_suppressed`. An unknown child code or a child's claim to IsOS's suppression code is rejected, including when source/core/run syntax is otherwise valid. EGIA codes are pinned to the reviewed 16-code owner policy fixture; unlisted codes remain closed. Plain stdout and non-JSON stderr are not mirrored into IsOS's shared stream. A malformed or oversized line is drained without buffering the remainder; the next valid line can still become the first ready or failure event. The collector preserves valid child timestamp, severity, code, node path, correlation and typed fields, and sets PID from its own child handle. EOS and EGIA own full diagnostics outside this shared stream.

Each selected child pipe has a bounded reader and writes an admitted event directly under the shared rotation lock. There is no intermediate event queue: a repeated eligible diagnostic is counted in a 256-key table, while first lifecycle, failure, ready and terminal events go directly to storage. Stop and child reap run independently of collector threads. The same serialized record is written to the source and unified files; a failed write increments `log_write_failed` without recursive logging. A source-file cap still leaves the unified copy. Private raw child stdout/stderr also rotate. The raw line limit is 8,064 bytes including newline; the normalized stored-line limit is 8,192 bytes including newline after adding observed PID. Rejected lines increment `log_ingest_rejected` and a bounded reason counter. An oversized raw line drains through newline before the next event is parsed. Producers trim only their already sanitized messages.

Deduplicate repeated eligible noncritical diagnostics inside one `(run_id,source,node_path,event_code)` key. The first event is written, duplicates increment a counter, and a summary is emitted no more often than every 60 seconds or at terminal flush. The first warning, every changed state, readiness, failure and terminal event passes. P07 owns retained first-event lookup and cursor behavior after rotation; live status remains the truth about health.
