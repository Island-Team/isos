# P06 deployment event design

[中文](../../../docs_cn/isos/design/events_cn.md) · [Owner contract](../interfaces/events.md) · [First use](../usage/get-started.md)

**Target design — not implemented.** The [event interface](../interfaces/events.md) owns the JSONL fields, limits and lifecycle rules. This page explains how IsOS should produce and collect them. The current `LogStore` already creates private rotating source files and `events.log`, and `manager_session_id()` already labels selected package events. It also parses some child JSON from both pipes, but drops the child's owner, node, run, correlation and metadata fields. Ordinary manager events lack run context. P06 replaces that lossy path while preserving existing log reads.

## Admission path

The API, CLI and Unix manager select one deployment and request correlation before work. Prelaunch package and graph failures use the current manager-session ID even when an earlier deployment is active; this prevents an Apply failure from appearing to belong to an unrelated running revision. After all P04/P05 preflight and secret resolution pass, Start allocates a deployment-run ID and records it with the supervisor before the first child starts. Restart creates a candidate run only when it reaches replacement; a failed preflight keeps the old active run. A failed replacement becomes terminal on its candidate run, and a restored prior specification receives a distinct recovery run. Idempotent Start returns the existing run. The manager passes the ID to EOS and EGIA as defined in the owner contract and retains it for stop, child recovery and status. One run can contain several automatically restarted child PIDs; correlation IDs distinguish attempts.

`LogStore` should accept an immutable event object only after a constructor validates the exact envelope and sanitizes it. The manager's own call sites emit fixed event codes and safe message templates with typed metadata; they never format an arbitrary error chain into a message. P01 receipt logging rechecks the requested `{id,version}` and copies only the available digest/commit fields from the verified receipt. A failed package verification with no trustworthy receipt emits null provenance instead of reading a possibly altered file. HTTP and CLI failures share the same event constructor so a failure appears once, before the public reply, with its actual diagnostic code and graph pointer. The schema-1 `log_append` socket only checks peer UID, so it cannot authenticate a caller's claimed child role. The compatibility adapter validates the old request and preserves `accepted:true` but replaces its source, code and message with the fixed `legacy_external` manager event defined in the owner contract. It does not assign an active deployment run or emit a child-ready event.

The `Supervisor` knows the selected child role, PID, active run and authorized node paths. It reads bounded stderr lines, strictly parses one JSON object without duplicate keys, verifies the child's claimed source/core/run against its role and active run, validates that an EOS child names only an admitted EOS node and an EGIA child only an admitted EGIA node, and applies code-specific safe-field rules. The selected EOS runtime may claim `source:eos`, its HTTP bridge `source:bridge`, its config server `source:config`, and the selected EGIA child `source:egia`; raw MuJoCo diagnostics remain under the EOS owner directory. A child cannot claim another role. The compiled IsOS `event_policy` table pins each selected role's exact codes, typed fields, severity and suppression class against reviewed owner P06 contracts. This includes EOS runtime-only `eos_events_suppressed`; IsOS alone emits shared `events_suppressed`. An unknown child code or a child's claim to IsOS's suppression code is rejected, including when source/core/run syntax is otherwise valid. EGIA codes remain closed until its owner catalog is reviewed and pinned. Plain stdout and non-JSON stderr are not mirrored into IsOS's shared stream. A malformed or oversized line is drained without buffering the remainder; the next valid line can still become the first ready or failure event. The collector preserves valid child timestamp, severity, code, node path, correlation and typed fields, and sets PID from its own child handle. EOS and EGIA own full diagnostics outside this shared stream.

Use one bounded ingestion queue and a reserved capacity for first lifecycle/failure/stop events. A saturated queue drops repetitive low-severity health/frame diagnostics first and increments a counter; stop and safe actuator shutdown never wait for a log disk write. The writer serializes once, writes the same bytes to the source and unified files under the current rotation lock, and exposes any write failure without trying to log that failure recursively. A source-file cap still leaves the unified copy. The raw child-line limit is 8,064 bytes including newline; the normalized stored-line limit is 8,192 bytes including newline after adding observed PID. The collector rejects a normalized-overfull record, increments bounded `log_ingest_rejected`, and drains an oversized raw line before parsing the next. Neither a long message nor an oversized child line is silently truncated by the collector. The emitter trims its own sanitized message before emission. UTF-8 truncation must preserve a valid boundary.

Deduplicate only identical noncritical periodic events inside one `(run_id,source,node_path,event_code)` key. The first event is written, duplicates increment a counter, and a summary is emitted no more often than every 60 seconds or at terminal flush. A changed state, warning, error, ready or terminal event always passes. The counter and summary describe suppression without raw payload. This bounds log volume without hiding the first event. P07 owns retained first-event lookup and cursor behavior after file rotation; live status remains the truth about health.
