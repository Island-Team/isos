# R04 skill-selection transaction

[中文](../../../docs_cn/isos/design/skill-selection_cn.md) · [Owner contract](../interfaces/skill-selection.md) · [Generated configuration](../interfaces/configuration.md) · [Package verifier](../interfaces/package-verification.md)

**IsOS selection slice independently reviewed; final merged-tip R04 gate pending.** R04 extends the implemented P01/P04/P05 and R03 boundaries. The graph selects a bounded list of exact native libraries on the EOS component; IsOS does not interpret ABI descriptors or execute skill code. EOS's host ABI and worker contract own that work. There is no new graph skill node, sequence runner, ActionList or second actuator path.

## Apply algorithm

1. Validate the saved `0.1.0` graph and exact `isos/process/component/eos` runtime component placement and resolved `aether-runtime`; `bridge`, `config` and other EOS-role components cannot select a host. Extend IsOS `ProcessSettings` and its G06 aggregate catalog after EOS adds generic `SettingType::ObjectArray` support. IsOS publishes the exact @v0.1 descriptor with both `env_from` and `skill_libraries` metadata and leaves @v1.1 unchanged. Run a raw-graph R04 prevalidator before generic `ProcessSettings` deserialization on Validate, Apply, Run and Restart: the current parser collapses nested errors to a node path and would lose the exact field/index pointer. Parse `skill_libraries` with an unknown-field-denying shape. Reject more than 16, duplicate `(id,version,library)` tuples, malformed pins and unsafe relative paths at their array-index JSON Pointers. The existing legacy graph reader does not project this setting.
2. Add every entry to the graph-wide P01 pin set. Reverify each exact package once, retaining the precise first graph pointer for a package failure. Require `kind:"skill"`; open each selected library without following links, check every path component, regular type, 1–64 MiB bound and SHA-256. Check the selected file, receipt, release and every regular payload file for same effective UID ownership and `mode & 0o022 == 0`, matching EOS's pre-worker verifier. Use a verified handle, never store-wide discovery or a recursive `*.skill.so` selection walk. More than one selected library per package is allowed; every path is explicit.
3. Probe the exact selected EOS runtime for `host-skill-abi-v2` if the list is nonempty. P05's selected-binary identity and feature diagnostic apply. Render `isos/skill-selection.json` from verified handles in sorted order. Include its hash in P04's final `files` inventory and include its package receipts in `packages`; compute generation with the existing canonical manifest algorithm. Recheck source file identity and digests before publishing the immutable leaf and selection map. A package or binary change requires a new Apply even with the same graph bytes.
4. Publish with P04's existing fsync, selection-map, required-marker and graph-rename order. A failure before the selection rename leaves the previous saved graph and active run. An uncertain rename is resolved by rereading the observed saved revision, map, marker and complete leaf, never by assuming publication succeeded.

## Run, replacement and recovery

IsOS's G06 aggregate catalog supplies its exact `isos.process.component@v0.1` descriptor with both `env_from` and structured `skill_libraries`. The older-EOS fallback clone supplies only `env_from` for skill-free graphs and cannot advertise or admit a nonempty selection. The historical EOS `@v1.1` descriptor remains unchanged.

Run/Restart execute the current G01/G06/P01/P04/P05 and R03 preflight under the deployment lock. They require an explicit schema-2 V2 selected leaf for nonempty selection, rehash the exact saved graph, selection file, package receipts and selected libraries, and compare a fresh rendering of the selection bytes with the manifest-listed file. They inspect the intended process-spec set and resolve all child secrets before active replacement. Only then is a new R03 run allocated and the selected EOS child given `EOS_SKILL_SELECTION_FILE`; the config, bridge, EGIA, MuJoCo and independent-service children never receive it. The env value cannot be supplied by the authored graph. A preflight failure preserves the active PID set and grants. An automatic EOS child restart in the same run retains this immutable file, while an explicit Restart rechecks it and rotates the R03 run/grants. A failed candidate is terminal and follows the manager's existing recovery path with a fresh run ID.

EOS validates the selected manifest and library content again before its skill catalog becomes ready. In particular, a linked payload can change between IsOS's preflight and EOS startup. EOS opens with nofollow, hashes and copies the bytes from that same descriptor into a private stage, and the confined worker loads that stage. Catalog admission cannot execute a handler; invalid ABI, descriptor or unsupported declared callback family fails before invocation. If a valid handler later requests a primitive it did not declare, the Broker denies that request after the handler starts and before Dispatcher release. R04's negative seam does not claim containment of arbitrary same-UID or kernel-compromising package code.

The current `restart_processes_with_plan` prepares a `Supervisor` and R03 grants, then calls `managers.remove(name)` and `active.supervisor.stop()` before EOS catalog inspection. The new transaction adds the [private candidate preflight](../interfaces/skill-selection.md#candidate-abi-preflight-isos-implementation-candidate) only for a nonempty selected host. `preflight_packages` still owns graph/P01/P04/P05 and selected-spec checks. The candidate `Supervisor` owns the new run ID and grants; its run scope remains unpublished while the probe runs. The probe itself cannot mutate the old manager map entry, child set or log scope.

1. Under the deployment lock, pin saved graph bytes and revision, selected schema-2 leaf, manifest/generation inventory, exact selected `aether-runtime` file and feature, rendered selection bytes, P01 receipts, release/payload/library digests, selected `--node-types` arguments and secrets/process specs. Verify the old run's grants as today; prepare the candidate grants only after these checks. Do not treat a `host-skill-abi-v2` feature claim as ABI admission.
2. Launch the exact selected binary with the EOS private preflight arguments and only the candidate verifier and selection file in a cleared manager environment. Supervise its process group with a single 90-second wall-clock deadline, bounded stdout/stderr capture and checked reap. Parse exactly one closed JSON line; compare success echo fields and every ordered library digest to the pinned inputs. Map valid rejection, invalid output, timeout and cleanup uncertainty to the four fixed IsOS codes. Never surface raw output or guest strings in logs.
3. On rejection, timeout, invalid output or a post-probe pre-stop check failure, retire candidate grants through a new checked API that returns errors and proves bundle removal. `Supervisor::stop()`/Drop are insufficient because they print retirement errors. Confirm probe process-group cleanup. If either is unconfirmed, report `skill_catalog_preflight_cleanup_unconfirmed` with precedence. Return before `managers.remove(name)` and keep the old PIDs, run ID, revision, grants and run scope. Do not allocate a recovery run for this pre-stop failure. Block another replacement until an unconfirmed candidate bundle is repaired.
4. After `ok:true`, immediately rehash saved graph, complete selected-generation inventory, executable bytes and P01 package/library inputs, verify candidate grants and confirm selected process specs still match. This is the last pre-stop gate. Keep the candidate bundle for launch. Then execute the existing old-child stop, run-scope publication and replacement start order. The new EOS independently repeats selected-file, grant, package, ABI and pure catalog-readiness admission with newly staged bytes; the probe result is never cached as authority. A failure after old-child stop uses the existing recovery path. An automatic same-run EOS restart repeats launch admission without replacement preflight.

The cross-owner selected-pin seam includes a P01-valid version `1`: EOS rejects it as `selection/selection_invalid` before old-child stop; IsOS reports fixed `skill_catalog_preflight_rejected`, retires candidate grants and retains the exact validated pin in the safe manager event. The event collector must not reapply EOS's stricter version grammar.

The probe can reject invalid ABI, unsupported callback, missing static primitive binding, duplicate identity and oversized catalog before old-child stop. It cannot prove live adapter health, Dispatcher state, R05 physical release fence or R06 actuator stop and simulator reap. A guest handler is never invoked by the probe; an undeclared call from a later valid handler is denied by EOS Broker before Dispatcher release. This preserves one actuator admission route.
