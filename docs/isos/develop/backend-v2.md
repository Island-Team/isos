# Develop and verify the v2 backend path

[中文](../../../docs_cn/isos/develop/backend-v2_cn.md)

Build the EOS Rust bins (`aether-profile`, `aether-runtime`, `aether-http-bridge`, `aether-config-server`), IsOS, and the MuJoCo simulator. Stage the real bundle with the MuJoCo repository's `tools/build-backend-bundle.py`. `isos pkg link island/mujoco-sim 2.0.0 <bundle>` registers a local development bundle. `isos pkg install` verifies a release archive first. `isos init` writes one editable shared graph; `isos config validate` and `apply` admit and save it. Graph edits must go through the same v2 registry and IsOS package projection. Use `ISOS_AETHER_PROFILE_BIN` when the validator is not on `PATH`; set `MUJOCO_ROOT` to the MuJoCo library root.

The IsOS source template is `templates/mujoco-graph-v2.toml`. `src/v2_starter.rs` selects local paths. `src/v2_backend.rs` resolves package receipts, descriptor and assets. `src/v2_process.rs` validates backend/device/socket references and supervises direct children. `src/http.rs` serves the workbench endpoints. EOS's registry and adapter live in its own `crates/` workspace; IsosUI owns the editor. Keep the package descriptor, graph node settings, and simulator payload structs separate.

For repeatable verification, run `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, and `python3 tests/clean_home_v2.py`. The harness stages a protocol mock bundle in a fresh home, checks missing assets and mismatched device admission, package removal guard, process ordering, revision immutability, discovery, camera capture, base/manipulator observation and movement, safe stop, restart, and logs. It measures five start/restart cycles and 200 HTTP→EOS socket requests. It does not test MuJoCo physics or native library loading.

On Linux x86_64, 2026-10-30, the 34 IsOS tests, Clippy, and formatting passed. The clean-home mock scenario passed. Fixed-workload median/p99 startup was 346.917/350.345 ms; median/p99 HTTP→EOS request latency was 10.148/10.469 ms at 98.4 requests/s. These include the IsOS manager's 50 ms poll cadence and local Python mock. Full output is in `logs/test/20261030-isos-package-run/`. A real simulator run remains to be measured on a host with `MUJOCO_ROOT` and the built C++ executable.

Foreground lifecycle check (2026-10-30, Linux x86_64): `cargo build`, `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, and `python3 tests/clean_home_v2.py` passed. The harness holds `isos init` and `isos run` as live processes, sends SIGINT to `run` and verifies all deployment children stop, then restarts through the API, sends SIGINT to `init`, and verifies child exit and control socket removal.
